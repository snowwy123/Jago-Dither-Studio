# Explore gallery validation

23 October 2026 · Dither 1.10.1 development preview

All 20 bundled cards were opened through the actual gallery in offline HTML. Every example produced a composition and rendered output; Undo restored the exact previous project each time. Browsing/closing alone did not alter the document. Still/Moving, search and collection filters were checked. Look, Move and Resources open the same gallery. Directions/recipes remain reachable in their own Explore sections. No HTTP requests or browser page errors occurred.

Thumbnails were generated by loading and rendering each real example in Dither, then reducing its output to a JPEG. These are original bundled sources, not external artwork. Light and Charcoal gallery layouts were inspected, including the search field and a narrow window.

The compiled Windows host opens the embedded Chrome Bloom Live project through the shared Resources example route, retains its independent layer looks and restores the previous project through Undo. Existing native screen/font/grid/optics/audio/video checks also pass. The 112 engine/model/codec tests pass, as do existing character/grid/palette/undo workflows and clip/directions/locks/favourites/export/cancellation workflows after the Explore navigation update. Two pre-existing shared-host compiler warnings remain unchanged.

Gallery project templates and image assets are embedded and gzip-packed at build time using Node built-ins. Images shared by projects are deduplicated by hash; matching Wobble starter frames are referenced rather than duplicated. Local decompression occurs when opening an example. No runtime service, download or additional package is introduced.

This pass changes discovery and packaging, not the treatment renderer. Previous preview packages remain intact. Public PDFs/website materials should use Explore → Examples at the next accepted release.
